* **A split's sub-PRDs pass `define` again.** F-PRD-05 counted a sub-PRD's AC ids from AC-01, while the Split Protocol has it keep the global ids its index assigns (AC-09..AC-17 stays AC-09..AC-17), so every sub-PRD that followed the protocol failed. A sub-PRD whose sibling index (`| Status | Split |`) has a row for it now has its ACs checked against exactly that row: none missing, none extra. Its FR and NFR ids still count from 01, and any other PRD is checked as before. Reported, with the fix, by @MussiDev.
